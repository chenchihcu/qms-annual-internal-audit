# 單一稽核工作區資料模型與升級規格

**狀態：已核准（2026-09-24）**

## 目標

將目前依九潤／正隆興切分的作業改成一個稽核工作區。日常操作不顯示公司切換、公司欄位或公司別篩選；同一份年度設定、部門、稽核計畫、人員名冊、查檢結果及改善台帳供同一組稽核與受稽人員使用。

適用標準、版次、證書／依據、程序來源仍是工作區的稽核範圍資料，不作為公司分區。實際適用性仍依證書範圍、合約、法規與受控程序確認。

## 單一工作區中的資料

| 作業資料 | 新工作方式 | 舊資料處理原則 |
| --- | --- | --- |
| 年度設定與年度封存 | 一個目前年度；每年度一份封存 | 依紀錄年度合併兩側封存；年份不同時先列入待確認 |
| 部門、程序風險與稽核計畫 | 一份部門清單、一列一個 QP／部門組合、一組月份 | 相同值合併；月份取聯集；負責人、文件等欄位矛盾時保留候選值並要求覆核，不靜默選邊 |
| 稽核人員、受稽人員與任命 | 一份人員名冊和年度任務 | 以員工編號識別同一人；同編號但姓名或資格衝突時暫不合併，列入覆核 |
| 查檢表與稽核結果 | 一份查檢快照；每題一個判定 | 相同判定合併；相異判定不推定結果，暫列待判並保留兩份來源值；既有事件快照不改寫 |
| NCR、觀察、第三方建議 | 各一份共用追蹤台帳；每筆代表實際不同事項 | 完全相同的重複資料去重；內容不同的紀錄都保留，識別碼衝突時建立新識別碼並更新其關聯 |
| 外稽準備 | 每個準備項目一個完成狀態；相關證據／附件可有多份 | 只有符合舊項目原完成條件的才轉為完成；單側完成等部分狀態留待確認，不自動算完成 |
| 回收區 | 一個回收區；還原回單一台帳原位置 | 保留原資料、年份及關聯，畫面不顯示公司欄位 |

## 遷移與回復

1. 遷移前匯出目前完整 JSON 備份；此備份留在使用者本機，不上傳。
2. 從現行儲存版本升級至下一版單一工作區格式。舊資料只有在新格式寫入成功、讀回並完成結構驗證後才切換使用。
3. 遷移只自動合併沒有歧義的資料。矛盾的人員、計畫或判定顯示精簡的覆核清單，保留原值供比較；未覆核的判定不得納入分數或標為已完成。
4. 原始備份可透過既有 JSON 匯入流程還原；不在程式中清除舊台帳或既有行程資料。
5. 既有公司名稱與公司別狀態只作為匯出備份中的歷史來源資訊，不出現在新工作區的導覽、表格、篩選或列印表頭。

## 外稽準備表

原始 seed 中的來源文字保留供追溯；日常表格改為單一「完成」欄，不再分列九潤、正隆興或合併狀態。需要不同證書、客戶或現場範圍的文件，作為同一準備項下的多份佐證管理。兩家公司關係核對不再作為目前流程的必填條件。舊完成狀態依該項原完成規則換算；資訊不足的項目保持待確認。

## 驗收條件

- 左側導覽及全站頁面不提供公司切換、公司別頁面或公司篩選。
- 年度計畫只出現一次；稽核與改善紀錄進入同一台帳，不因舊公司來源重複計數。
- 查檢題目只可有一個有效判定；舊值矛盾時不會悄悄算分或產生結案狀態。
- 外稽準備表每項只有一個完成狀態，列印、匯出與畫面一致。
- 年度切換、深連結、匯出／匯入、回收與還原，在遷移後仍保留既有功能。
- 用新舊格式 fixture 執行遷移預演與回復驗證；不以使用者目前瀏覽器資料做測試。
- 在確認遷移規則前，不變更使用者實際瀏覽器的 localStorage。

## 已核准的執行規則

無衝突資料自動合併；計畫或人員等欄位衝突列為待覆核；相異查檢判定不自動決定；外稽準備只有滿足原完成條件才轉為完成；遷移前先下載本機 JSON 備份。使用者已核准此規則，再實作儲存格式升級與全站單一工作區切換。
