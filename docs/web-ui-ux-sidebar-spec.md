# QMS Web 專案 UI/UX 規格：稽核流程左側選單

## 目的與適用範圍

本規格定義主導覽的位置、流程順序、圖示與寬度。桌面版以左側選單取代目前頁首的橫向分頁群組；主要頁面內容維持在選單右側。此規格不授權改變 route、稽核資料、判定、計分或儲存語意。

## 導覽項目與流程順序

左側選單呈現 11 個作業入口（無 PDCA 分組標題）。儀表板是跨流程總覽，放在流程項目前方；其餘依年度規劃、稽核執行、結果追蹤排列。外稽準備自 2026-10-09 起是查檢表的檢視模式（頁內「查檢｜外稽準備」切換），不另佔側欄；`#tab=prep` 仍有效，此時側欄標示「查檢表」為目前頁。利害關係人自 2026-10-09 起同樣是方案風險的檢視模式（頁內「程序風險｜部門利害關係人」切換），不另佔側欄；`#tab=stakeholders` 仍有效，側欄標示「方案風險」為目前頁；部門 O／S 仍不取代程序固有風險。系統設定不提供證書範圍、證書編號、適用性或「稽核基本資料」；稽核事件由年度計畫或查檢表直接開啟，不另設稽核日程頁。

這個 UI 順序是依目前功能語意及 README 的外部稽核先後關係整理；專案目前沒有單一受控文件完整定義所有導覽步驟。若正式作業程序的順序不同，以適用的受控程序覆核並更新本表。

| 順序 | 作業入口 | `TabId` | 流程定位 |
|---:|---|---|---|
| 0 | 稽核總覽 | `dashboard` | 年度摘要、待辦與追蹤數量 |
| 1 | 風險來源登錄 | `risk-sources` | 登錄客訴／重大變更並點選關聯程序（點選＝計入）；勾選「已全部登錄」；程序類型對照（2026-10-09 自方案風險拆出） |
| 2 | 方案風險 | `risk` | 7 因素矩陣自動統計（系統來源自動帶入，人工值選理由）；儲存全部、確認、核准 |
| 3 | 人員合格名單 | `personnel` | 維護人員主檔、資格、任命與年度陪稽 |
| 4 | 年度稽核計畫 | `plan` | 月格只排程（空白↔擬定）；結果由查檢推導顯示；自動編排先預覽再套用，可核准計畫 |
| 5 | 查檢表 | `audit` | 執行查檢、保存證據、開始／回報並鎖定紀錄 |
| 6 | 觀察事項 | `observations` | 記錄及追蹤觀察事項 |
| 7 | 不符合 | `ncr` | 登錄不符合並追蹤矯正狀態 |
| 8 | 第三方建議 | `suggestions` | 追蹤第三方稽核建議 |
| 9 | 待改善追蹤 | `followups` | 合併未結 NCR、觀察與建議；點列深連結 `#tab=…&record=…` 開到該筆 |
| 10 | 系統設定 | `system-settings` | 程序與紀錄、備份與匯出、回收區 |
| — | 利害關係人（方案風險檢視） | `stakeholders` | 標定部門利害關係人與 O／S；不列側欄 |
| — | 外稽準備（查檢表檢視） | `prep` | 內部稽核與管理審查完成後，準備外部稽核；不列側欄 |

系統設定分為「稽核資料」、「備份與匯出」、「回收區」。稽核資料只有「程序與紀錄」，不設子分頁；正式紀錄保存位置以自由輸入指定，不提供寫死的預設位置。2026-10-10 依 AS9100 條文內容審查移除「系統流程」與「進階評分設定」（條文未要求加權分數或流程說明圖）；`scoringRules` 仍保留於資料與備份供相容，查檢完成判斷不依分數。設定頁不顯示證書範圍、證書編號／引用、適用性、AS9100 版本，以及「稽核基本資料」「管理系統認證證書」「稽核程序與正式紀錄位置」。全表單 Excel 已包含適用標準，設定頁只保留一個全表匯出入口。還原備份前須先下載目前資料，資料變更後需重新下載。證書文字仍留在資料與匯出，不在設定頁編輯。

「外稽當日行程」專頁已移除；既有行程資料保留於本機狀態與 JSON 備份，不因移除頁面而刪除。舊 `standard`／`procedure` hash 導向系統設定，`schedule` 導向查檢表，`onsite` 導向外稽準備檢視。

本表是產品層級的導覽順序規格；程式以 `src/lib/navigation.ts` 維護唯一的導覽資料來源，排序須符合本表。修改順序時維持既有 `TabId`、hash 解析與頁面對應，並同步更新規格與實作；不可只改畫面排列而讓鍵盤順序、行動版選單或路由順序不同步。

## 文字與標題範圍

- 保留各功能項目現有的文字名稱，文字仍是主要辨識方式，圖示用來輔助掃描。
- 不新增裝飾性的側欄大標題或流程群組文字標題；若需要分段，優先用間距或細分隔線。
- 側欄藍卡只顯示產品名（如「QMS 年度內部稽核」），不可點擊、不另列「首頁」；第一個流程項「稽核總覽」即回家入口。
- 年度計畫、方案風險、利害關係人的 `PageToolbar` 不重複頁首年度／主任稽核員任命、程序與利害關係人互代說明或已存檔計數（缺口條與列印標頭已涵蓋）。
- 窄螢幕頂欄只保留「選單」開關，不另加「首頁」按鈕。
- 本規格不定義功能標籤的文案改寫、字型、字級或標題視覺風格。

## 圖示

- 每個導覽項目配置一個易辨識且語意相符的圖示；同一選單使用一致的線條、尺寸、視覺重量與對齊方式。
- 優先重用專案已有圖示資產；若沒有既有資產，使用簡潔的 inline SVG。未經評估不得為此單獨新增圖示套件。
- 圖示不得取代可見功能名稱；文字與圖示需共同呈現目前選取狀態。狀態不可只靠顏色表示，並須保留鍵盤 `focus-visible` 樣式。
- 與可見文字重複的圖示設為裝飾性（例如 `aria-hidden="true"`）。若受窄螢幕限制採圖示專用模式，互動項目仍須有可存取名稱及可見 tooltip；此模式需另外驗證，不得靜默隱藏名稱。

## 側欄寬度與版面

- 側欄寬度以「最長功能名稱 + 圖示 + 間距 + 必要內距」為基準，選用能完整顯示名稱的最小寬度；避免固定使用過寬欄位或以空白填滿側欄。
- 桌面寬度下功能名稱維持單行、完整可讀。若名稱或字型改變，依實際 CJK 字型度量重新確認寬度，不以靜默截斷換取窄欄。
- 主內容區應使用側欄以外的可用寬度；兩者之間只保留一致、必要的版面間距。
- 側欄不可遮擋主內容、列印內容、頁首警告或鍵盤焦點。列印時沿用現有隱藏導覽的行為。

## 長表格分頁

- 資料列超過 10 筆的作業表格與觀察事項清單以頁碼分頁；少於或等於 10 筆時不顯示分頁控制。
- 預設每頁 10 筆，使用者可切換 20 或 50 筆；控制列顯示目前範圍與總筆數，並提供上一頁、頁碼、下一頁。
- 變更篩選條件或資料年度時回到第一頁；帶有紀錄深連結時仍定位至該筆所在頁。
- 分頁不改變資料順序、篩選結果、編輯／儲存對象或匯出範圍；帶有紀錄深連結時，直接開啟該紀錄所在頁。
- 螢幕只顯示目前頁的資料列或清單項目；列印仍包含完整內容，避免只印出當前頁。
- 寬表格沿用有界水平捲動及內容適配欄寬；分頁不以縮小字體、截斷文字或整頁水平溢出處理欄位寬度。

## 響應式與無障礙

- 桌面寬度（驗收至少 1280px）顯示常駐左側選單；窄螢幕（驗收至少 375px、768px）提供可收合側欄或抽屜，依主內容所需最小寬度決定切換點。
- 收合控制需以語意按鈕實作，具可見焦點、可存取名稱及正確的展開狀態；鍵盤使用者可開啟、關閉並操作所有項目。
- 目前頁面使用語意化導覽與選取狀態（例如 `nav`、`aria-current="page"`），視覺閱讀順序、DOM 順序與鍵盤 Tab 順序一致。
- 寬表格仍須提供明確的水平捲動提示；側欄收合不得造成表格、表單或主要操作被裁切。

## 驗收條件

1. 桌面主要導覽位於頁面左側，11 個作業入口順序符合本規格表及 `src/lib/navigation.ts` 的 `SIDEBAR_TABS`。
2. 所有保留作業功能仍可從導覽進入；hash 支援 `tab`、`audit`（查檢表）、`section`（觀察前／本年度）、`record`（NCR／觀察／建議紀錄 id），已移除入口的舊 hash 導向相鄰作業頁。
3. 每個功能項目有一致且語意相符的圖示；功能名稱可完整閱讀，沒有多餘的側欄空白。
4. 375px、768px、1280px 寬度均可使用；窄螢幕能以鍵盤開啟及操作收合選單。
5. 以鍵盤檢查 focus-visible 與操作順序，並檢查螢幕閱讀器名稱、選取狀態及展開狀態。
6. 確認導覽不改變稽核流程、判定、計分、localStorage 或列印表單的資料語意。
