# QMS 年度內部稽核系統

供內部稽核員與主任稽核員在桌面瀏覽器使用的本機稽核作業工具。計畫、人員、稽核結果與改善紀錄共用一個工作區；稽核資料保存在目前瀏覽器的 `localStorage`，不取代組織正式受控紀錄。

## 本機啟動

```bash
npm ci --include=dev
npm run dev -- --open    # http://127.0.0.1:43124
npm test
npm run lint
npm run build
```

Windows 桌機可直接開啟 `啟動稽核工具.bat`。程式只使用 `127.0.0.1:43124`；若該埠已被占用，啟動會停止並提示檢查，不會自動切換網址，避免產生分離的瀏覽器資料。

## 作業流程

1. **系統設定**：確認稽核程序代碼、程序版本、正式紀錄保存位置與評分規則。證書範圍與適用性留在既有資料，不在此頁編輯。
2. **利害關係人、人員**：維護部門、人員資格及年度任命。
3. **年度計畫、方案風險**：建立稽核範圍、負責人、月份與風險評估。
4. **內部稽核**：從計畫建立查檢表；開始後依題目記錄判定與客觀證據，完成必要欄位後回報。
5. **結果與改善**：維護 NCR、觀察事項與第三方建議，追蹤期限、措施與結案證據。
6. **外稽準備**：維護準備項目、備註與日期；內稽完成狀態依年度稽核資料推導。

稽核總覽只保留年度狀態、待處理事項與常用入口。年度計畫和查檢表保留快照；已回報的查檢表鎖定。月格只記錄排程，稽核結果由查檢與改善資料推導。

## 資料安全

- 首次讀取舊格式資料時，先下載遷移前 JSON 備份，再驗證並套用單一工作區格式。
- 無衝突資料自動合併；計畫、人員等矛盾資料列入覆核；不一致的查檢判定保持待判，不自動計分。
- 自建 NCR、觀察、建議、人員與查檢項目可移入回收區還原；永久清除需再次確認。
- JSON 匯入、Excel 匯出、列印與回收區操作均在本機瀏覽器完成。
- 正式稽核證據與受控文件仍須依組織既有管制方式保存。

## 查檢表來源

- 稽核查檢種子：`src/data/checklists.seed.json`
- 外稽準備來源：`src/data/externalAuditPrep.seed.json`

原始來源文字保留供追溯；外稽準備畫面與匯出採單一工作區欄位。
